MetaCamp2026 游记

发表于 2026-08-24

刘姥姥进大观园咯！

一人一间大床房？水果送到房间里？？什么叫夜床服务？？？

啊啊，能来线下决赛真的刷新好多认知。

我决赛主要负责 conquest 以至于那几天看到 contest 就 ptsd，赛前感觉这个题上 GPU 可能是有前途的，但别的题更加依赖 GPU，于是作罢。

拿到题，case 从初赛的 1 个变成了 5 个。我第一反应是先把 CPU 集群占满跑 baseline。咋这么慢？

哎我是不是应该估算一下每个 case 要跑多久。看 case 数据范围能有一点感觉，但是不同 case 算法差很多也不好比。有一个 case，agent 跟我预估 15min 以内跑完，实际跑了 50min。迭代结束后的执行路径没有被注意到。

哎我是不是应该先优化一点再跑。一开始就是开了三四个 session，一个 agent 看一个 case 分头优化。但问题是 slurm 排长队，场面十分混乱。有的 agent 交完 job 排队就不管了，结果 job 被其它 agent 不小心取消了。还有的 agent 交完 job 排队后转头研究目前在跑的 job 去了。最后才想到开 subagent，所有的 job 都让主 agent 调度，无奈等混乱结束，只剩大概 50 分钟，收效甚微。

哎我优化到多少该停呢。我当时采取的策略是优化到比榜上最快的快为止。目标终未实现，榜单已换新天。Conquest 的所有提交都被我藏到了封榜后，反正没罚时。营造出了 (+6) 的节目效果，对不起队友，不过更有节目效果的还在后面。

虽然我藏得有点过分，但谁知道别人呢。

哈哈，一语成谶。

明确的 validator，宽松的数值容差，还不限制算法修改。这说明什么问题呢。大的要来了！看最高分队伍的分享，被吓到眩晕瘫坐，那一刻就像看到原子弹爆炸。推动其他队伍实现共产主义了倒是。

这个题考验选手的乱搞水平。感觉 agent 已经 hack 成精了。Prompt 根本不应该是优化 xxx。说优化就已经默认固定算法流程了，至少我心里还在这么想，传达出来的 prompt 肯定是这样的。这个题问的是，你能不能造个快一百倍而且输出差不多的东西出来，管他算法是啥呢。

Open Day 讲到，计算效率能改变思维方式，高昂的实验成本会使得探索偏向谨慎保守。之前参加的超算比赛都太松弛了，没有体会到限制并发的痛苦。以 baseline 的速度，整场比赛 8 个小时都跑不了几个 job，把所有 case 跑完都成问题，那留给乱搞的机会就少了。静态代码分析还是离不开实践检验，或许更好的办法是一开始跑一些缩小版 case 的 baseline。我几乎所有 job 都占满了 4 节点，有了小 case 就可以用更少的节点，减少排队。

发的东西太多了，我为啥没有带旅行箱。怎么还会发毛绒玩具的。牛来。妈妈。广为人知的奶牛表情包。最有收获的地方还是和大家一起聊天的餐桌。大家都好牛。

回家的飞机上拍到了很棒的晚霞。这还有点运气成分。我自己线上值机的时候，只剩一个座位可以选，并不靠窗。但赶到机场去值机，又说有一个靠窗的位置空着。我没多想就换了，结果刚好在西边。
